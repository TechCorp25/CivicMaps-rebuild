# Municipality service routing (F06)

F06 uses the [development hostname standard](../civicmaps-naming-pack/DEVELOPMENT-HOSTNAMING-STANDARD.md). Platform and Alpha/Beta CommandMAPS have separate HTTPS origins beneath `dev.civicmaps.com.au`, delegated from VentraIP to Route 53. Reserved EnforcementMAPS/reporting names do not deploy those scaffold apps. Council administrator activation remains F07; routing never marks a municipality Active.

## Application boundary

Migration 008 adds an explicit host manifest, immutable-context/resource references, version, state, lease, safe probe result and event history. Existing sessions gain nullable route/version columns; migration and seed replay preserve existing records. Local development keeps its explicit loopback mode; an unrecognised routing mode fails closed. Deployed API mode must be `CIVICMAPS_ROUTING_MODE=ingress` with distinct private ingress and probe tokens of at least 32 characters. Generate these on the runtime; never commit or publish them.

Caddy accepts the three explicit hosts, rejects client Forwarded/X-Forwarded-Host/X-Forwarded-Proto/X-Civicmaps-Ingress headers and preserves the authority for backend validation. TLS SNI and Host must agree. The backend listens only on loopback, checks the ingress token and peer, rejects duplicate/ambiguous authority and permits only canonical registered hosts. DNS case is canonicalised; ports, trailing dots and other authority forms fail closed. Unknown authorities have no application route. Caddy's management API is disabled.

Council authentication requires the host's authorised context before issuing a session. Every subsequent session must match the manifest ID/version, and context selection must agree with the route. Cookies are Secure, HttpOnly, SameSite Strict and host-only in ingress mode. Origin/CSRF checks remain active; same-site sibling domains do not bypass the exact origin check. Platform and council paths remain separate. Manually copying a cookie to another host is rejected server-side.

A council route requires its explicit context/resource mapping, current unrevoked/effective binding, successful F05 job, schema version 2 and enabled resource. The private readiness probe also opens a real F05 runtime TLS database connection and checks the data table. It returns only manifest/context identifiers. Normal access requires state ready and a result less than five minutes old. The routing worker rechecks after 60 seconds, with a 15-second fetch timeout, no redirects and normal public TLS verification. It holds a 60-second fenced lease. A failed probe records a generic error and requires operator retry; repeated worker crashes exhaust the attempt budget. Rechecks retain ready access while the last successful result is fresh.

`GET /api/platform/municipalities/:id/routes` and detail responses expose safe routing status. CSRF-protected retry/withdraw actions require the current route version and an authenticated platform operator. They increment version, invalidate old sessions and record the actor/event. Manifest ownership/context/hostname changes require the trusted structural writer; those actions cannot create a user grant. UI shows ready/pending/failed/withdrawn and verification expiry separately from data provisioning and administrator activation.

## Proposed development deployment

The reviewed [CloudFormation template](../../infrastructure/f06/aws-development.json) creates a dedicated Sydney t3.micro runtime, 16 GiB encrypted gp3 disk, IMDSv2, standard CPU credits, static IPv4 and three exact DNS A records in the existing development zone. Only ports 80/443 are inbound; SSH/API/PostgreSQL are not public. SSM provides management. The existing private F05 database accepts connections from the new runtime security group. The privileged F05 acceptance runner stays stopped.

The runtime IAM role reads only the two synthetic F05 credential secrets and F06 release artefacts and assumes a separate two-namespace storage role. Each request still intersects storage access with the single-municipality session policy. It cannot read the F05 master secret or create resources. The master ARN in configuration is a reference needed by the existing target validator; it grants no permission. The EC2 role and control-plane process remain trusted brokers across the two synthetic councils.

Caddy 2.10.2 obtains and renews exact-host public ACME certificates. This avoids an additional ALB or paid exportable certificate. HTTP serves approved-host HTTPS redirects and ACME validation only. The Node API serves the two built web apps and same-origin API. Its dedicated control database lives on encrypted local EBS, loopback only, with SCRAM authentication. The API's control-plane login has BYPASSRLS to perform the existing authentication/broker queries, but has no superuser/database/role-creation powers; operational callbacks explicitly SET LOCAL ROLE to the existing restricted council role. This is a development broker boundary, not protection from a compromised broker or a production deployment.

The bootstrap generates a private acceptance password instead of the repository's public local password. It preserves it and the control database across redeploys, seeds synthetic users only and imports the two exact retained F05 resource references. New registrations are paused. No first council administrator is activated. Keep `/etc/civicmaps/runtime.env` private; systemd reads it as root for the unprivileged services. Do not print it or raw provider errors. Application readiness is not a tested production availability/recovery commitment.

## Rollback and verification

Withdraw the exact route using the operator action/current version. The backend immediately rejects requests and old sessions; no data or job history is deleted. Retry changes version and requires a new successful probe before access returns. For a whole deployment pause, stop the three F06 systemd services and remove only the exact owned development DNS records if needed; preserve manifests, disks, F05 data and audit. Never delete the F05 stack or infer deletion ownership from a prefix. Route withdrawal is separate from general council suspension (F09).

Local validation: `npm run check`, sequential `npm run test:platform:browser` and `npm run test:commandmaps:browser`. The optional actual-Caddy handler contract uses `CIVICMAPS_CADDY_BINARY=<verified binary> node tests/ingress-contract.mjs`; it intentionally serves loopback HTTP and is not public TLS evidence. Validate the template with cfn-lint and the scoped Guard rules, Caddy with `caddy validate`, and bootstrap with `bash -n`. These checks cannot substitute for live deployment acceptance.
