## Outcome and boundaries

An activated administrator of a newly provisioned synthetic council can provision explicitly authorised dispatcher/officer access. Those staff complete create → assign → acknowledge → attend → close in their own council. Another council cannot discover, assign, mutate or read the audit of that work. ADMIN identity alone grants no operational-record access. Existing pack enforcement, retained review, session revocation, concurrency and idempotency remain effective.

This completes F11, not merely another dispatch presentation precursor. F11D and F11E are already merged. F12 dedicated officer web and F13 mobile remain later work. Release follows the sequence below using the established deployment environment and release runbook. New production topology, expenditure, real council onboarding, suspension policy, evidence/infringement issuance, offline sync and new legal authority are outside this phase. Deployment must use a compatible, tested migration and recovery procedure; synthetic fixture migration is never a customer identity migration. Synthetic local migrations needed by F11 must preserve records and use a reviewed compatibility/recovery plan; do not admit an older application that bypasses new enforcement; do not run them against retained/cloud databases.
