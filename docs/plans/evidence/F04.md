## Delivered behaviour

Registration creates the municipality, pending first admin, queued synthetic job, ordered steps, receipt and attributable registration audit in one transaction. Registration replay returns the same job and does not replay temporary passwords. Historical registry fixtures are not automatically enqueued.

The separately runnable worker atomically claims a lease and records attempts, invokes the adapter between transactions, then checkpoints only while its token and lease remain current. Duplicate delivery and restart retain the job and stable step keys. A synthetic effect committed before a crash is reconciled rather than created again. Each step has three automatic attempts per recovery cycle; transient failure has bounded backoff and permanent failure is visible. Operator retry/reconcile retain completed steps and history. Successful synthetic jobs never activate a municipality.

Platform detail presents queued/running/waiting/failed/succeeded state, steps, attempts, resource IDs and bounded error summaries. Active jobs poll, terminal jobs stop polling, and manual refresh recovers an unavailable detail response. Keyboard retry, unavailable action recovery and expired-lease reconcile are exercised in Chromium. The adapter mode and pending real infrastructure/admin activation are visible.

## Contracts, rollback and limitations

See [job runbook](../../development/provisioning-jobs.md) and [scoped brief](../F04-preparation.md). PostgreSQL queue locking was checked through Context7; changed React components were checked against the React best-practices skill, with Hooks dependency checks enabled. Pause worker and registration/recovery mutations, retaining registry, jobs, steps, effects and audit. Restore compatible binaries and allow lease recovery. ## Resolved gotchas and handoff

Importing the worker module before disposable-environment creation caches the database pool against the base database, producing missing-table errors. Tests now import it after environment setup. Keep this ordering on future test files.

Long council emails/slugs gave the detail grid/flex children an oversized minimum width. The 390-pixel acceptance assertion caught it; explicit shrinkable children and text wrapping fixed it. Preserve the synthetic long-ID cases.

The Platform Vite fixture can select port 5173 even when configured with port 0; running the fixed-port CommandMAPS harness concurrently caused a port-in-use failure. Sequential browser execution passed; it was a fixture collision, not an application failure.

F04 publication and Empirical completion/gotchas are recorded; the ledger is review_ready for owner review. F05 is next after owner merge and D01: choose an approved isolation/provider boundary and implement real disposable data resources through the adapter. F04 does not resolve D01 implicitly.

## PR #10 assessment corrections

The independent assessment found two UI lifecycle defects: a delayed manual refresh could show the previous council's job after navigation, and a failed scheduled poll could remain stopped after a successful manual refresh returning the same job state.

Manual refresh now restarts the existing cancellable detail effect. That effect owns all detail reads and schedules subsequent polls from the returned job state. Recovery mutations also check their route/session generation before publishing a notice, error or refresh. Navigation and session cleanup invalidate old completions. This follows React's [Effect cleanup guidance](https://react.dev/reference/react/useEffect), consulted through Context7; no worker, API, schema or provider scope changed.

Both regressions were also checked against the original PR source and failed as expected: stale council/job content and queued status after worker completion. Browser regression coverage holds an Alpha response across navigation to queued Beta, then checks that Beta retains its own job. A separate scheduled-poll 503 is recovered manually while still queued; real synthetic worker completion must subsequently appear through polling. The worker fixture waits for reconcile to return queued before launching its synchronous worker processes.

Validation: `npm run check` passed lint, formatting, both TypeScript checks/builds and all 41 integration tests. `npm run test:platform:browser` passed the existing flows and both regressions. Use `CIVICMAPS_DATABASE_URL` (not generic `DATABASE_URL`) for the disposable test database configuration. F04 remains scoped to synthetic provisioning and awaits owner review/merge; the F05 dependency and D01 decision are unchanged.
