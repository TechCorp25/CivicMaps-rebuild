## Resolved deployment gotchas

The initial stack creation was rejected by automatic approval review pending explicit public exposure/cost approval. The owner approved the concrete deployment and live tests; creation then succeeded. This block is resolved.

PostgreSQL `SELECT FOR SHARE` requires UPDATE privileges even for read-only authentication locks. A broad identity UPDATE grant was rejected and was not applied. Migration 009 instead supplies narrow void-returning SECURITY DEFINER row-lock helpers, revokes PUBLIC execution and grants execution only to the trusted broker. Ordinary identity writes remain restricted; concurrency regressions and actual cloud login pass.

Root umask/source and CA permissions initially blocked unprivileged migration/resource reads; explicit public-file permissions and root-only credentials fixed this. API health initially worked while HTML returned 404 because the terminal fallback preceded static serving; handlers now mount before that fallback, readiness checks the built entry, and browser acceptance covers the regression. Live failure injection uses the authorised OS/database operator for one owned synthetic resource, rather than expanding application grants. Lessons are recorded separately in Empirical.
