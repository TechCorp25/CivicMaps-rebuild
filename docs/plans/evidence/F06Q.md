- **A3:** detail reads remain serial, use ten-second request timeouts, poll settled routes every 15 seconds and active work every two seconds, recover automatically after refresh failure, and abort on navigation/logout. The mounted routing component expires readiness without clicks and hides current-ready status when refresh is unavailable.
- **A5:** health reports local/ingress routing mode separately from synthetic data, without secrets.
- **A4 preparation:** a staged existing-runtime update script and [controlled release/recovery procedure](../../development/service-routing.md#controlled-update-and-rollback) preserve private configuration, control data, identities, route versions and history. They establish a private backup and owned restore proof before migration, preserve withdrawn routes, stop routing first and recover prior source on a failed release. The script is syntax-checked, **not live executed**.
